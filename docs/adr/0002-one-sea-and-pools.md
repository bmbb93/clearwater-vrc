# 水は Sea ひとつと Pool いくつか。Pool は Sea の仕組みの複製で、互いの間は範囲で切り分ける

Clearwater はワールドに水面が 1 枚ある前提で作られていた（コントローラーが持つ水は 1 つで、水中かどうかは高さだけで決めていた）。リゾートのように、海と建物の 1 階・2 階のプールを混在させるために、水を複数にする必要が出た。

すべての水を同格に一般化する（どの水も Coast・打ち寄せる波・波音を持てる）のではなく、Sea はこれまでどおりひとつとし、それとは別に Pool を何個でも置けるようにした。Pool は Sea と同じシェーダーと波の計算（位置によらない繰り返し模様）を共有し、マテリアルを複製して自分の水面の高さと床を持つ。床は、ユーザーが作ったプール本体のメッシュを User terrain と同じ方法でベイクする。どの水の中か（水中の霧、下から見た水面、波紋、触れたときやタップ）は、Pool の範囲（上から見た四角と、底から水面まで）で決める。Sea は Pool の範囲を穴として抜く（水面・地面・当たり判定・光の模様）。

Pool に求められたのは、海の表現（打ち寄せる波・生成地形・水平線・波音）ではなく、潜れる静かな水と屋内での見え方だった。同格に一般化すると、コントローラーとシェーダーのすべてが「どの水の Coast か」を持つ必要があり、ベイクしたデータもプロジェクトにひと組という前提から作り直しになる。一方、Sea の仕組みを複製すれば、既存の水面・水中・光の模様がそのまま使え、プールがないワールドは今までとまったく同じ見た目と負荷のままになる。

## Consequences

- 水越しに別の水は映らない。画面の取り込み（GrabPass）を名前付きで共有しているため、後から描かれる水には先に描かれた水が映らない。
- Pool の範囲は、ワールドの軸にそろった四角と高さで表す。回転したプールや不整形なプールは、それを囲む四角で近似する（水は、プール本体が水面より低い所にしか見えないので、四角が多少大きくても困らない）。
- 波紋は、見ている人がいる水にしか付かない（波紋のシミュレーションはひとつ）。
- Pool には打ち寄せる波がない。水面の揺れは Sea の波を弱めたもの（Wave strength）。
- 屋内の Pool は、空の代わりにリフレクションプローブを映す。プローブがなければ部屋は映らない。
- Pool の数に比例して増えるのは、見えている Pool の描画と、毎フレームの範囲の判定（Udon の小さなループ）だけ。
